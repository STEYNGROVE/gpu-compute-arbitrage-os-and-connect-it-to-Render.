# Phase 20 targeted security audit

Release policy remains **SIMULATION / DISCOVERY ONLY**. New preview routes have no ability to dispatch a GPU request, mutate a production journal, cancel a provider resource, collect a payment or post revenue. No Render configuration/deployment, paid resource, production database test or unsolicited message was used.

## Findings, repairs and regression coverage

| Severity | Confirmed issue | Repair and test |
| --- | --- | --- |
| HIGH | Direct treasury/credit reservation repository methods lacked a local simulation barrier | Treasury posting, direct SETTLED-record insertion and reservation create/consume/release now deny before SQL; legacy internal credit primitive requires isolated-test mode. Named boundary tests assert zero calls and LIVE-setting denial |
| MEDIUM | Supplier balance response parsing was unbounded; loose identity/error shapes could look authenticated | Shared streaming 1 MiB JSON reader, six-second request deadline, strict IDs/GraphQL errors, explicit UNVERIFIED independent status. | MEDIUM | Transaction and rollback errors could expose underlying details | Stable public error, name/code rollback log and non-enumerable original error. Regression checks callback/rollback/detail strings do not escape and clients release |

| LOW | Legacy commercial draft expiry allowed invalid/timezone-dependent dates | Strict shared date parser; invalid calendar and timezone-free expiry tests |

Development failures in the new SQL/types were fixed before final validation. No security check, assertion threshold, TLS constraint or financial gate was disabled to obtain a pass. The strict launch audit still exits 1 with five unresolved blockers.

## New code review

* **Authentication/authorization:** actual `requireOwnerAuth` guards all three Phase 20 endpoints. Missing, invalid and CUSTOMER credentials reject; valid owner access remains bounded. Existing Phase 19.1 cookie/header rules, explicit preview opt-in, forbidden URL session credentials and expired/revoked sessions are retained.
* **Input/response limits:** schema fields and reference lengths are bounded; unknown gateway fields reject. Owner previews enforce 32 KiB model bodies and a 30/minute per-process limiter. Supplier collection permits one inflight call per configured provider, 30-second cooldown, six-second deadline and bounded receipt serialization; real collectors must still use a bounded transport before parsing. Fixed two-provider maps cannot grow from arbitrary provider names. Recovery returns at most 100 records.
* **SSRF/DNS/TLS:** new evidence URLs are references, never fetched. They reject unsafe schemes/credentials/query-token references. Feed collection still uses secure DNS pinning, public IPv4 validation, HTTPS/certificate checks, timeouts, byte bounds and redirect rejection. Existing fixed supplier endpoints retain TLS/default verification, redirect rejection and bearer headers; account/host compatibility remains externally unverified. No caller can supply a transport, signer, collector or database through the new HTTP request schema.
* **Evidence authority:** exact kind/subject/account/time/facts binding and cryptographic collector signature checks precede independent receipt status. Default trust roots are empty. OFFLINE_TEST cannot verify independent commercial truth. SIMULATION/MANUAL origin never verifies. Public-key trust roots are trusted server construction inputs, not request data; no raw credential is part of the receipt/interface. Actual collector independence, key rotation/revocation and immutable archive are unresolved.
* **SQL and concurrency:** all application values use parameters. New journal transactions use SERIALIZABLE isolation, global reservation advisory locking, per-request row locks, exact payload digests, event-key uniqueness and bounded retries for known-aborted serialization/deadlock errors. SQL constraints preserve zero real money and denied authority. Lost commit replies remain uncertain and require lookup. Fresh process/connection recovery and abrupt pre-commit process exit are tested in a disposable database.
* **Audit:** identity/budget/deadline mutation and event UPDATE/DELETE are rejected. A deferred constraint couples state and audit event commits; version/hash/head checks detect inconsistencies. This is local tamper evidence, not administrator-resistant WORM storage. A DB administrator can bypass privileges/triggers or rewrite a whole hash chain; production role design and external anchors remain dependencies.
* **Money/numeric safety:** new quotation uses bounded integer minor units and BigInt intermediate arithmetic, explicit upward cost rounding and downward utilization revenue. Missing/negative/nonfinite/overflowing cost inputs reject. FX basis is explicitly MINOR_TO_USD_CENTS; currency pair, source and expiry must match. Quotes remain draft, with unverified capacity/contracts/payments and zero realized revenue.
* **Financial lockdown:** existing direct purchasing, payment settlement, outbox, treasury, withdrawal and HTTP locks remain. New real execution/cancellation always denies, including LIVE flags. Simulation reconciliation cannot promote real invoice, balance or revenue verification. The simulation database is not the real financial ledger.
* **Errors/secrets:** new error responses contain stable codes; no provider credential or raw SQL error is echoed. Test environments exclude ambient credentials/database targets; generated TLS and disposable database credentials are local fixtures and are not committed. Basic tracked-file scanning and registry advisory audit are limited checks, not a formal absence-of-secrets/vulnerabilities proof.

## Review limits

This audit covers the new modules and affected supporting paths plus focused review of the existing financial repositories, locks and migration controls. It does not certify every legacy balance/precision calculation, historical schema, deployed ingress, secret configuration, distributed rate-limit behavior or live provider API. Historical migrations include potentially destructive repairs and were not executed against production or an unknown baseline. Full financial-system acceptance is still open.
