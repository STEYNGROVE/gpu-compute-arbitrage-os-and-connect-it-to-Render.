# Security verification

The combined candidate preserves owner authentication, strict production sessions, customer role isolation, rate limits, financial lockdown, signed evidence, replay protection and simulation boundaries. The new hunter router uses owner authentication before every handler; tests submit anonymous, invalid owner keys and customer sessions to its sensitive routes. The main application retains a global owner gate for legacy internal APIs. Public liveness, authentication and bounded commercial enquiry routes are intentional exceptions; they cannot purchase or settle anything. See the route declaration inventory and runtime test results; local handler markers alone are not proof of complete authorization.

Production session cookies remain HttpOnly, Secure and SameSite=Strict. Development auto-session creation is excluded from production. Customer provisioning is owner controlled; no open privileged signup was introduced. Application MFA is not independently established; external GitHub/Render account MFA must be confirmed by the owner where supported. No credential, token or production financial configuration was changed.

Read-only discovery uses fixed official operation URLs, public IPv4 DNS validation/pinning, verified TLS, response-size and deadline limits and redirect rejection. Akash's compatibility query uses the same controls and runs only after HTTP 501, never on generic failures. Public feed transport has separate TLS, DNS rebinding/private-address and timeout regression suites. SQL values remain parameterized. New metadata tables enable RLS and revoke PUBLIC privileges; least-privilege application grants/policies must be reviewed against actual deployed roles before production application.

Raw upstream supplier errors are no longer propagated by the shared transport or catalog collection logs. Migration errors remain bounded identifiers, environment inventory contains names only, public diagnostic output contains allowlisted public observations, and no production data is exported. Dependency and tracked-file checks are reported per command in tests.json, not assumed from historical CI. Heuristic credential scans cannot prove absence of every possible secret format.

Journal records remain local hash chained, serialized and application append-only; they are not externally anchored WORM storage. The optional committed-head suggestion is deferred, not described as mandatory public-launch evidence or as a substitute for durable external anchoring. A filesystem administrator can replace the head and chain together even if a head file is added. Modes B/C remain blocked on independently durable evidence and reconciliation.

Remote runtime security has a **confirmed critical exposure**: public staging returned backend bundle and source-map prefixes with HTTP 206. Anonymous owner paths returned 403; that narrow check does not establish all role policies. Draft PR #57 contains the isolated source repair; the combined candidate also includes it. Deployment and post-deployment rejection checks remain outstanding. This observation does not establish credential leakage. Render workspace confirmation, account MFA and complete runtime access review remain external dependencies. No critical finding was waived to obtain a test result or GO decision.
