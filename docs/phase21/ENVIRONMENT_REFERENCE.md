# Environment variables — names only

Source-wide names appear in baseline-inventory.json; this is not a deployed-secret inventory. Render tools did not expose a names-only environment read. No secret values were retrieved.

Required discovery profile: NODE_ENV=production, APP_OPERATING_MODE=DISCOVERY_ONLY, STRICT_AUTH_ENFORCEMENT=true, RENDER_GIT_COMMIT (exact deployed 40-character revision); PORT (platform port, validated); DATABASE_URL (secret, authenticated TLS by default). OWNER_API_KEY, CUSTOMER_API_KEY, ESCROW_SIGNING_SECRET, QUOTE_LOCK_SECRET, AUDIT_CHAIN_SECRET must be distinct strong backend secrets. DATABASE_SSL_CA may identify a locally mounted trusted CA; DATABASE_SSL enables verified TLS outside production. DIRECT_URL is optional fallback and must receive the same trust/privilege review. All configured fallback URL aliases are validated under the same policy.

Optional plaintext exception: DATABASE_INTERNAL_TRANSPORT=render-private-network plus RENDER_SERVICE_ID and RENDER_INTERNAL_DB_HOST matching the exact Dashboard internal hostname, port 5432 only. This explicitly accepts Render private-network, DNS and environment integrity as the trust boundary; hostname matching does not authenticate a database server. Confirm same workspace/region and environment isolation before any separately approved configuration change. Missing opt-in or host uses verified TLS; explicit sslmode=require/verify-ca/verify-full, ssl=true/1, DATABASE_SSL=true or either CA setting always requires certificate and hostname verification. Render internal self-signed TLS may fail this stronger policy; do not disable verification to connect. Use an existing externally reachable verified TLS endpoint where permitted, or retain the documented private-network exception after owner review. No infrastructure/configuration changes are made by this patch.

URL parameters are limited to sslmode, ssl, sslrootcert and application_name, without duplicates. sslrootcert is preserved; conflicts with DATABASE_SSL_CA fail closed. Client keys/certificates, driver host/port overrides and timeout overrides are rejected. CA file readability is checked when constructing the pool; readiness configuration assessment only checks policy. Plaintext outside production is limited to loopback fixtures. Connection acquisition, query and statement limits are each five seconds; max pool size 15 and idle timeout 30 seconds. Review aggregate connection budget per replica against the actual database plan.

Forbidden release settings: GPU_PURCHASING_ENABLED=true, GPU_EVIDENCE_VERIFIER_READY=true, any DB_MIGRATION_EXECUTE, NODE_TLS_REJECT_UNAUTHORIZED=0, DATABASE_SSL_REJECT_UNAUTHORIZED=false, ENABLE_STUDIO_AUTH_FALLBACK=true, ALLOW_PREVIEW_SESSION=true and frontend VITE_* secret-like variables. LIVE flags never override unconditional lockdown.

Discovery optional: LEAD_SOURCE_REGISTRY_JSON (bounded reviewed source registry), legacy LEAD_RSS_FEEDS only when registry absent. Empty registry disables ingestion. Provider/payment/treasury keys are unnecessary and should be absent for discovery production. GROQ_API_KEY is optional only after model/privacy/quota approval; no agent startup requires it.

Isolated tests: NODE_ENV=test, DISABLE_JSON_PERSISTENCE=true, ALLOW_ISOLATED_GPU_DB_TEST=YES, TEST_DATABASE_URL generated exclusively by disposable harness; DATABASE_URL excluded. Never point these tests at production or a shared database. No production .env file should be loaded; explicit development only may load local .env.
